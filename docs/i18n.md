# Localization

The platform is bilingual: Greek (`el`, default) and English (`en`).

## Routing

- Every page uses a locale prefix: `/el/...` and `/en/...`.
- `/` redirects through middleware to the negotiated locale.
- Resolution order: explicit URL locale, `NEXT_LOCALE` cookie, `Accept-Language`, then `DEFAULT_LOCALE` (Greek).
- The language switcher writes `NEXT_LOCALE` and replaces the current path with the new locale, preserving query parameters such as `?tab=game`.

## UI strings

- Catalogs live in `messages/el.json` and `messages/en.json`.
- Components use `useTranslations` (client) or `getTranslations` (server). Never place visible copy directly in a component.
- `tests/messages.test.ts` fails when the two catalogs have different key sets.
- For interpolation, use ICU placeholders, e.g. `"deckProgress": "Κάρτα {current} από {total}"`.

### Adding a string

1. Add the key to `messages/el.json`.
2. Add the same key to `messages/en.json`.
3. Run `npm test -- tests/messages.test.ts`.
4. Use it via `t("namespace.key")` in a component.

## Generated content

- Cards, questions, options, and explanations are stored per locale.
- The generator produces Greek and English variants in one structured response so answer keys and option IDs stay aligned.
- Student mode requests the active locale and falls back to the lesson's primary locale, showing a visible fallback notice.
- Narration is prepared in both locales when a teacher requests a video variant; each video variant is then generated on demand and stored per locale.

## Formatting

Use `src/lib/format.ts` for dates, numbers, percentages, and durations. It uses `Intl` with the active locale, so Greek and English output differ correctly.
